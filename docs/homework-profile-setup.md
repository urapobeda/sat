# Домашки и профиль ученика

## SQL: порядок запуска

Рабочая база не изменялась. Перед включением нового кода откройте Supabase → SQL Editor и выполните целиком, по очереди:

1. `supabase/migrations/harden_homework.sql`.
2. `supabase/migrations/add_student_profile.sql`.
3. `supabase/verify-homework-profile.sql` — только проверка объектов и привилегий.

Предполагается, что существующие таблицы приложения и Supabase Storage уже созданы, а `add_roles.sql`, `add_groups.sql`, `add_assignments.sql`, `add_assignment_feedback.sql` и прежние миграции защиты результатов уже применены. На новой базе сначала нужен существующий базовый SQL проекта; эти два файла не заменяют базовую схему. Старые миграции защиты/домашек после новых не запускайте: они могут вернуть старые версии функций и политик. Оба новых файла проверены на повторном запуске.

Миграции выполняются в транзакциях. При ошибке изменения файла откатываются; исправьте причину, прежде чем переходить к следующему файлу. После успешного применения для отката интерфейса можно вернуть предыдущий код, сохранив новые таблицы/колонки. Не удаляйте `teacher_notes`, аватары, результаты и колонки профиля ради отката. Старую логику раскрытия ответов и лимитов не возвращайте без отдельной проверки безопасности.

## Домашки

- Срок попытки: серверный `started_at + time_limit_minutes`; ещё 30 секунд допускается на доставку сохранения. После этого поздний ответ не записывается, ранее сохранённые ответы автоматически оцениваются.
- Автосдача происходит при сохранении/открытии попытки, открытии списка домашних работ, отчёта учителя или проверке связанного вопроса в практике. Фонового cron нет. `submitted_at` ограничивается моментом истечения срока с запасом, чтобы позднее открытие страницы не делало результат искусственно просроченным.
- SQL не бросает исключение в той же транзакции, где автоматически сдаёт работу: это откатило бы автосдачу. Серверный маршрут обнаруживает завершённую попытку и возвращает 409. Изменение ответа после обычной сдачи также запрещено.
- Таймер рассчитывается от серверного начала попытки; обновление страницы не возвращает время. Сервер остаётся источником истины независимо от часов браузера.
- Вопросы, `kind`, `paper_id`, группа и лимит времени замораживаются после первой попытки, включая попытки бывших участников группы. Редактор показывает подсказку и кнопку дублирования. Копия — новый черновик с настройками и вопросами, без результатов/комментариев учеников.
- Для `after_submit` правильные ответы доступны после завершения всех разрешённых попыток либо после дедлайна задания. Пока последняя попытка выполняется, старый разбор тоже не раскрывается. `after_due` и `never` сохраняют свои ограничения.
- Question Bank проверяет ограничения домашки на сервере до проверки ответа. Заблокированный ответ не сохраняется как правильный/неправильный и не содержит правильного варианта, объяснения или признака правильности. Необязательный `sessionId` не позволяет обойти эту проверку. Ограничение относится к проверенному аккаунту; публичный гостевой режим не удалён.
- У `authenticated` нет прямого EXECUTE на `assignment_has_submissions`. Политика удаления использует узкую definer-функцию, которая сначала проверяет право управлять заданием. Удаление черновика без попыток работает; результаты с попытками не удаляются.

### Past Paper homework — временно недоступно для создания

Полноценная привязка `exam_attempts` к заданию и модульный отчёт в этой работе **не реализованы**. Тип скрыт в форме создания, API отклоняет его даже с корректным `paperId`; дублирование такого задания тоже не предлагается. Существующие задания и самостоятельный раздел Past Papers сохранены. Не выдавайте старое сопоставление попыток только по `paper_id` за полноценную привязку.

## Профиль

- `/profile` доступен из меню аккаунта. Содержит аватар, поля профиля, группы и учителей, дату SAT, цель, известные оценки и отдельные секционные оценки/графики, навыки, домашки, историю и стрик в часовом поясе браузера. `/progress` сохранён и доступен по ссылке.
- Оценки показываются только из сохранённых результатов и помечены как неофициальные. Отсутствующие секционные баллы не вычисляются задним числом. Счётчик вопросов относится к уникальным проверенным вопросам Question Bank. Повторные ответы не увеличивают его.
- Время практики — записанное время правильных ответов, как предусмотрено существующей системой. Оно не выдается за полный хронометраж всей активности. Неделя — последние 7 дней; старые записи без времени не дополняются вымышленными значениями.
- Домашняя статистика использует последнюю попытку каждого доступного опубликованного задания. История содержит сохранённые завершения практик, тестов и домашних работ.
- `/teacher/students`: поиск по имени/своей группе, порции по 25, Load more, сортировка загруженных строк. `/teacher/students/[id]`: тот же профиль и приватные заметки. Ученик никогда не получает содержимое заметок в API.
- Роль и идентичность проверяются по Supabase на сервере; приватные результаты не читаются через service-role. RLS допускает только владельца, учителя текущих групп ученика и администратора.
- Добавлены отдельные разрешающие SELECT-политики. Старые restrictive owner-guards `FOR ALL` пришлось разделить на чтение и запись: иначе PostgreSQL отвергает SELECT учителя несмотря на новую разрешающую политику. Условия владельца для INSERT/UPDATE/DELETE сохранены; студент не получает доступ к другим ученикам. `guard_profile_role` не заменяется. `test_answers.correct_answer` и `question_solutions` остаются закрыты для браузера.

### Аватары

Бакет `avatars` приватный. В `profiles.avatar_url` хранится путь `USER_UUID/FILE`, а API выдаёт короткую подписанную ссылку. Upload/replace/delete разрешены только в своей папке. Учитель может читать аватары своих учеников, администратор — все. Лимит бакета 2 МБ, разрешены JPEG, PNG, WebP, GIF; SVG не разрешён. Ограничивающие политики защищают папки даже при наличии старой широкой Storage-политики. Реальная загрузка в рабочий Storage не выполнялась; проверены конфигурация бакета, RLS и клиентская валидация.

## AI Tutor

По умолчанию выключен. Весь имеющийся UI и API сохранён, но скрыт/отключён. Для включения требуется `NEXT_PUBLIC_AI_TUTOR_ENABLED=true` при сборке и перезапуске. Ключи и `.env.local` не менялись. Выключенный endpoint возвращает 404 и не вызывает платную модель.

## Проверки

В `test:unit` добавлены профильные тесты API/аналитики, расширены тесты практики, домашек и флага тьютора. SQL-набор `npm run test:student-profile:sql` использует отдельный локальный PGlite и проверяет повторное применение миграций, таймер/запас, поздние ответы, автосдачу, пересдачи, копирование, заморозку, отзыв EXECUTE, старые restrictive-политики, изоляцию учителей/учеников, заметки, запрет изменения роли и папки Storage. Для запуска нужен установленный `@electric-sql/pglite` либо переменная `PGLITE_PATH` с путём к его `dist/index.js`. Рабочая база в тестах не используется.

Браузерная проверка профиля использовала тестовый ответ локального API, а не запись в рабочую базу: проверены показатели, форма и обновление имени. Проверка живых аккаунтов и Storage возможна только после ручного применения SQL.

Финальная проверка: `npm run lint`, `npm run test:unit`, `npm run build`, `npm run test:student-profile:sql` — выполнены успешно. В браузере подтверждены три графика (общий, R&W, Math), отсутствие горизонтального переполнения профиля при 375 px и отсутствие кнопки Ask AI Tutor при выключенном флаге. В тестовой домашке с лимитом 5 минут и серверным началом 2 минуты назад таймер показал 3:00; после обновления продолжил отсчёт (2:45), не вернулся к 5:00. Запросы этих тестовых экранов перехватывались только в отдельной локальной вкладке; реальные работы не сохранялись. Снимок `work/homework-profile/profile.jpg` в рабочей папке Codex содержит синтетические QA-данные.
